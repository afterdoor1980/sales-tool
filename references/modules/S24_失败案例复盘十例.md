# S24 失败案例复盘十例

> 版本：v1.0（正式稿）
> 篇章：十三、案例篇
> 模板类型：类型E（案例萃取类）
> 适用业务模式：甲乙均可（5个甲案例、5个乙案例）
> 前置依赖：S22（萃取方法论）、S18（严重客诉转入本模块）、S21（落标转入本模块）
> 模块目的：让团队从失败中提炼教训，避免同类问题重复发生

---

## 与S22/S23的边界说明

本模块和S23同样是用S22 RCA法萃取的最终成果，只是萃取对象是失败案例而非成功案例。字段结构做了针对性调整：新增"后续补救情况"（如实记录是否尝试补救及结果，不美化），"教训与规避规则"拆分为"个人行为准则"（当下该怎么做）和"组织机制建议"（组织层面该建立什么机制预防类似情况），使失败案例的复盘价值从"个人吸取教训"上升到"组织流程改进"层面。

## 案例一（甲）：底线让价失守

| 字段 | 内容 |
|---|---|
| 编号 | S24-01 |
| 案例背景 | 大额订单客户强硬要求突破S10-04底线让价 |
| 关键失误点 | 销冠为促成签约，未按规定转交主管审批，自行突破底线给予额外折扣 |
| 实际处理过程 | 私自承诺超出权限的价格，事后补报主管 |
| 结果 | 短期内成交，但该客户后续每次续约都以"上次的价格"为基准要求同等或更大让步，价格体系被破坏，且消息在同行业间传开，多个客户效仿要求 |
| 后续补救情况 | 主管事后发现，与该客户重新沟通说明特殊让价为一次性个案，后续续约仍按标准框架执行；但客户仍多次以"上次价格"为由要求同等待遇，补救效果有限，最终通过提供其他非价格类增值服务（优先响应）部分缓解关系张力，价格纪律的负面影响未能完全消除 |
| 个人行为准则 | 底线让价的审批流程不能因"眼前这单"而绕过，一次突破会变成客户预期的新常态，损害的是整个价格体系而非单笔订单 |
| 组织机制建议 | 建立审批记录系统留痕机制，凡涉及底线让价的审批需在系统中留痕且定期（如季度）抽查核实一线是否存在未经审批擅自让价的情况 |

## 案例二（甲）：决策链误判导致资源浪费

| 字段 | 内容 |
|---|---|
| 编号 | S24-02 |
| 案例背景 | 销冠将某基层对接人误判为最终决策人，投入大量拜访和方案设计资源 |
| 关键失误点 | 未按S05识别置信度机制持续验证角色判断，长期基于未经验证的初始判断推进 |
| 实际处理过程 | 数月后才发现真正的采购决策权在老板手中，且老板对本次合作已无兴趣 |
| 结果 | 前期投入的资源全部浪费，错失与真正决策人建立联系的窗口期 |
| 后续补救情况 | 发现误判后销冠尝试重新接触老板，但因此前长期"冷落"了真正决策人，重建信任又耗时3个月，最终勉强恢复合作，但错失了原本可能更早达成的合作规模 |
| 个人行为准则 | 决策链判断需要持续验证而非一次判定后固守，识别置信度低时应尽早安排验证动作，而非等到资源投入很多后才发现误判 |
| 组织机制建议 | 将S05决策链地图的"识别置信度"字段设为强制填写项，规定置信度为"低/中"的客户每次拜访后必须更新验证进展，由主管定期抽查决策链地图的更新情况 |

## 案例三（甲）：客诉响应迟缓引发流失

| 字段 | 内容 |
|---|---|
| 编号 | S24-03 |
| 案例背景 | 客户反馈产品质量问题，销冠因当时手头事务繁忙未及时响应 |
| 关键失误点 | 未按S17/S18响应时限要求处理，超时48小时才回应，且未主动上报主管 |
| 实际处理过程 | 客户在等待期间情绪从"轻微不满"升级为"强烈不满"，最终响应时客户已决定终止合作 |
| 结果 | 客户流失，且在行业交流中提及此次经历，造成一定口碑损失 |
| 后续补救情况 | 意识到问题后销冠紧急联系客户道歉并提出补偿方案，但客户已决定终止合作，补救未能挽回该客户，仅避免了负面口碑进一步扩散 |
| 个人行为准则 | 响应时限不是可以灵活变通的建议，而是防止问题升级的关键窗口，超时本身就会独立成为新的、更严重的问题 |
| 组织机制建议 | 建立客诉响应时限的系统自动提醒和超时上报机制，超过响应时限系统自动通知主管介入，而非依赖一线人员主动上报 |

## 案例四（甲）：竞品对比失当引发反感

| 字段 | 内容 |
|---|---|
| 编号 | S24-04 |
| 案例背景 | 客户提及在对比竞品，销冠为凸显己方优势，主动贬低竞品的具体负面传闻 |
| 关键失误点 | 违反S20职业道德红线（不得诋毁竞品声誉），使用了未经核实的负面信息 |
| 实际处理过程 | 客户当场对这种做法表示反感，认为销冠"格局较小" |
| 结果 | 客户转而选择该竞品，明确表示"不喜欢这种诋毁同行的方式" |
| 后续补救情况 | 销冠事后未做特别补救，仅在后续与其他客户沟通时调整了话术方式；该客户最终选择竞品，未能挽回 |
| 个人行为准则 | 诋毁竞品不仅有职业道德风险，往往也直接导致客户观感变差，坦然呈现己方优势远比贬低对方更有效 |
| 组织机制建议 | 将职业道德红线（不诋毁竞品）纳入入职培训必考内容，并在S11/S20话术库的禁忌话术项中反复强化提示，同时建立内部反馈机制，发现类似案例及时纠正而非放任 |

## 案例五（甲）：转介绍激励滥用

| 字段 | 内容 |
|---|---|
| 编号 | S24-05 |
| 案例背景 | 销冠为完成转介绍数量指标，对老客户介绍的多个明显不匹配对象照常发放完整激励 |
| 关键失误点 | 未按S15激励与转介绍质量挂钩的规则执行，只看数量不看质量 |
| 实际处理过程 | 大量时间被用于跟进和筛选完全不匹配的低质量线索 |
| 结果 | 转介绍数量指标达成，但实际转化率极低，销售资源被严重浪费 |
| 后续补救情况 | 主管发现后暂停了该销冠当月的转介绍激励发放，并要求其重新按标准筛选后续转介绍对象，此后该销冠转介绍转化率有所提升 |
| 个人行为准则 | 激励机制必须与质量挂钩执行，否则会异化为"数字游戏"，反而拖累真正有价值的工作 |
| 组织机制建议 | 转介绍激励发放前增加S03判定结果的强制关联校验，系统层面对未完成S03判定的转介绍对象不允许直接发放激励，而非依赖事后稽核 |

## 案例六（乙）：方案与需求脱节

| 字段 | 内容 |
|---|---|
| 编号 | S24-06 |
| 案例背景 | 项目负责人为节省时间，跳过S08需求挖掘环节，直接套用其他项目的方案模板 |
| 关键失误点 | 未按S09"贴合而非套模板"原则设计方案，方案价值点与客户实际关注维度完全不匹配 |
| 实际处理过程 | 方案讲解会上，客户明确指出方案没有针对性，会议不欢而散 |
| 结果 | 项目直接落标，且客户对公司专业度产生质疑，短期内难以再获得同类项目机会 |
| 后续补救情况 | 项目负责人事后申请二次拜访机会，重新走S08需求挖掘流程，但客户已对公司专业度产生疑虑，二次机会申请被婉拒，未能挽回 |
| 个人行为准则 | 需求挖掘环节不能因赶进度而省略，方案脱离真实需求的代价远大于多花时间做好前期调研 |
| 组织机制建议 | 方案设计流程（S09）中增设强制检查点，方案提交内部评审前必须附上对应的S08需求挖掘记录作为佐证材料，缺失该材料的方案不予评审通过 |

## 案例七（乙）：投标因格式问题废标

| 字段 | 内容 |
|---|---|
| 编号 | S24-07 |
| 案例背景 | 项目团队在标书编制质量上花费大量心血，技术方案本身具有竞争力 |
| 关键失误点 | 临近截止时间赶工提交，跳过了S21-05标书评审环节的废标风险点核对 |
| 实际处理过程 | 提交后发现报价的数字金额与大写金额不一致 |
| 结果 | 被判定为无效标，直接失去评标机会，前期投入的方案设计资源全部浪费 |
| 后续补救情况 | 团队尝试联系招标方说明情况、申请复议，但格式类问题通常没有申诉空间，未能挽回，只能作为经验教训记录在案 |
| 个人行为准则 | 无论时间多紧张，废标风险点核对环节都不能跳过，方案质量再高也弥补不了低级格式失误造成的一票否决 |
| 组织机制建议 | 将S21-05废标风险点核对设为标书提交系统的强制流程节点，未完成核对清单确认的标书不允许在系统中标记为"可提交"状态 |

## 案例八（乙）：暂停供货执行不透明引发纠纷

| 字段 | 内容 |
|---|---|
| 编号 | S24-08 |
| 案例背景 | 客户逾期付款，公司决定暂停后续供货 |
| 关键失误点 | 未按S19暂停供货执行机制的规范操作，一线人员未提前明确告知客户暂停的具体条件和恢复条件，仅系统自动暂停 |
| 实际处理过程 | 客户在不知情的情况下发现订单被搁置，认为是单方面违约，引发争议升级 |
| 结果 | 客户在结清欠款后仍对合作关系心存芥蒂，后续订单量明显下降 |
| 后续补救情况 | 项目负责人在客户结清欠款后主动上门解释暂停供货的政策初衷和执行流程，并提供了一定的关系修复礼遇，客户关系逐步缓和但未完全恢复至此前水平 |
| 个人行为准则 | 暂停供货的执行必须配合清晰、及时的客户沟通，而非仅靠系统自动操作，程序合规不代表沟通到位 |
| 组织机制建议 | 将客户提前告知义务纳入S19暂停供货执行流程的强制步骤，暂停操作前系统需确认"客户告知"环节已完成才允许执行暂停 |

## 案例九（乙）：一线擅自承诺无法兑现

| 字段 | 内容 |
|---|---|
| 编号 | S24-09 |
| 案例背景 | 严重客诉场景，客户情绪激动要求立即给出解决方案 |
| 关键失误点 | 项目负责人未按S18升级机制第一时间上报公司高层及法务，为平息客户情绪当场做出超出权限的赔偿承诺 |
| 实际处理过程 | 事后发现该承诺公司无法兑现（涉及金额远超合理赔偿范围） |
| 结果 | 承诺无法兑现，客户认为被二次欺骗，情绪进一步激化，最终诉诸法律程序 |
| 后续补救情况 | 公司高层介入后尝试与客户重新协商合理的赔偿方案并道歉说明情况，但客户信任已严重受损，最终虽未升级到诉讼阶段，但客户彻底终止了合作关系 |
| 个人行为准则 | 情绪激动的场景更需要按流程升级处理，而非为快速平息情绪做出超出权限的承诺，无法兑现的承诺比拖延处理伤害更大 |
| 组织机制建议 | 严重客诉场景下，一线人员的应答权限在系统层面直接限制（如系统提示"此级别需高层审批方可承诺具体赔偿方案"），从权限设置上杜绝擅自承诺的可能性，而非仅依赖流程规定的道德约束 |

## 案例十（乙）：只讨好单一角色忽视否决权角色

| 字段 | 内容 |
|---|---|
| 编号 | S24-10 |
| 案例背景 | 项目负责人与技术把关人建立了良好关系，技术方案获得充分认可 |
| 关键失误点 | 未按S05角色影响力优先级判断，忽视了财务这一"否决型"角色的预算顾虑，未投入足够精力沟通 |
| 实际处理过程 | 技术评审顺利通过，但财务审批环节因预算问题被搁置，且此前未与财务建立过实质沟通 |
| 结果 | 项目在财务审批阶段无限期搁置，最终不了了之 |
| 后续补救情况 | 项目负责人意识到问题后紧急安排与财务的沟通，尝试提供更详细的成本论证材料，但审批周期已错过内部预算窗口期，只能等待下一财年重新申请，合作严重延误 |
| 个人行为准则 | 技术层面的认可不能替代否决型角色（如财务）的顾虑处理，资源投入需要按角色影响力优先级分配，不能因某个角色关系好就忽视其他关键角色 |
| 组织机制建议 | 将S05"角色影响力优先级判断"纳入项目周报的强制汇报字段，要求项目负责人定期汇报对每个决策链角色（尤其否决型角色）的沟通进展，管理层可及时发现资源分配失衡的情况 |

## 本模块专属验收细则

| 检查点 | 标准 |
|---|---|
| 失败类型覆盖多样化 | 是否覆盖不同类型的失败原因（底线失守、角色误判、响应迟缓、职业道德、激励滥用、方案脱节、废标、执行不透明、擅自承诺、角色忽视等） |
| 七字段完整 | 是否包含案例背景/关键失误点/实际处理过程/结果/后续补救情况/个人行为准则/组织机制建议 |
| 补救情况如实记录 | 是否如实记录补救尝试及结果，不美化处理，包括补救失败或效果有限的情况 |
| 组织机制建议具体可执行 | 是否提出具体的系统/流程改进建议，而非仅停留在个人行为准则层面 |
| 关联其他模块编号 | 是否恰当引用相关模块的规则，体现失误是对既有规则的偏离而非无据可依 |
| 与S18/S21衔接 | 是否包含源自严重客诉（S18）和落标（S21）转入的案例，呼应已建立的衔接关系 |

## 课件页要点

1. 强调失败案例复盘的目的是"规避同类问题"而非追责，营造安全的复盘氛围，鼓励团队坦诚分享失误。
2. 讲解"个人行为准则"和"组织机制建议"两个层面的区别，让学员理解光靠个人自觉不够，企业需要建立系统性的预防机制。
3. 讲解补救情况时强调"不是所有失败都能挽回，但补救尝试本身也是重要的学习内容"，避免学员误以为失败就是终局、无需再采取任何行动。
4. 现场练习：让学员分组讨论其中一个失败案例，尝试用S22的RCA法反向分析"如果销冠当时怎么做，结果会不同"，并为该案例设计一条尚未提出的组织机制建议。
