> 版本：v1.2（更新：补齐类型A标准字段——"首层提问"更名为"标准话术"，新增"话术意图（四维度）"和"升级路径"字段；新增甲"质量维度"、乙"成本维度"两条完整四阶段示范链条，使需求维度清单的迁移逻辑不再只是道理陈述，而有第二个可对照实例）
> 篇章：六、需求挖掘篇
> 模板类型：类型A（话术库）
> 适用业务模式：通用（提问框架一致，深挖内容按甲乙调整）

> 模块目的：让销售能挖出客户真实需求和顾虑，而非表面需求，为后续方案和报价打好基础

## 一、本阶段沟通前准备要点（对应S07的模块范围承诺）

S07（拜访前准备清单）与本模块的关系是"准备"与"执行"之别，而非两次分开会面之别——**很多情况下，S08的需求挖掘提问就发生在S07准备的同一次拜访里**，尤其甲类客户常见的情况是简短介绍后直接进入需求挖掘。因此S07的拜访前准备工作，本身就应当包含对本节内容的预习，而不是假设需求挖掘一定要等到"下一次"拜访。乙类客户由于决策链复杂，确实更可能把初步接触和深入需求挖掘分成不同会面，但这不是强制规则，需结合实际情况判断。

本节内容：

| 准备事项 | 说明 |
|---|---|
| 提前明确本次要挖掘的重点方向 | 结合S05决策链地图，确认本次沟通对象的角色关注点，提前想好该从哪个提问阶段切入（不必每次都从背景类问起，若已有初步信息可直接从难点类开始） |
| 准备好追问路径的心理预期 | 提前预想客户可能给出的2-3种回答方向，分别对应哪种追问路径，避免临场反应不过来 |
| 明确本次沟通的角色边界 | 若本次沟通对象只是决策链中的一环（如仅技术把关人在场），提前想清楚哪些信息需要后续桥接给其他角色，而非本次一次性问全 |

## 二、提问逻辑总览（含追问路径）

| 提问阶段 | 目的 | 首层提问后的追问路径 |
|---|---|---|
| 背景类 | 了解现状 | 若客户回答简略→追问具体细节（数量/频率/流程）；若客户主动多说→顺势引导到难点类提问 |
| 难点类 | 挖掘具体问题 | 若客户说出一个难点→追问"这个情况多久出现一次""具体是哪个环节"；若客户说"还好、没什么大问题"→转换角度问对比性问题 |
| 影响类 | 让客户意识到难点的实际代价 | 若客户轻描淡写→追问量化影响；若客户已经表现出重视→可直接推进到方向确认 |
| 方向确认类 | 确认解决方向 | 若客户认同方向→可自然过渡到方案设计环节；若客户犹豫或修正方向→回到难点类重新挖掘 |

**通用兜底规则（单阶段内）**：若同一阶段追问2-3轮后客户依然给不出实质内容（并非防御性回避，而是对方确实缺乏相关信息，如基层对接人不掌握全局情况），不再继续追问，按S03/S05已建立的"信息不足"逻辑处理——记录为信息不足，更新至S05决策链地图，转向其他更合适的角色获取该信息，或留待后续接触补充，不在当次对话中反复逼问。

**整体升级路径（四阶段全部走完仍未获得真实需求方向）**：若完整走完背景→难点→影响→方向确认四阶段，客户依然含糊其辞、未透露真实需求方向或顾虑，不应强行推进到方案设计阶段（贸然做方案容易文不对题）。应转为：① 重新评估是否接触到了正确的角色（参照S05角色影响力优先级判断，可能问错了人）；② 若角色正确但信息仍不充分，将当前进展标注为"需求不明确"，暂缓方案设计，安排下一次接触前先通过其他渠道（内部教练、公开信息）补充背景了解；③ 不因"已经聊了很久"而勉强推进，沉没成本不是继续推进的理由。

## 三、需求维度清单（重要：四阶段逻辑应在每个维度下复用，而非只示范单一线索）

上述"背景→难点→影响→方向确认"是**提问的阶段逻辑**，与之正交的是**该覆盖哪些需求维度**——本文档第四、五节的示范覆盖了"交付/效率类"（甲、乙各一条完整链条）和"质量/风险类""成本/预算类"（分别新增一条完整链条），其余维度可参照示范自行展开，而非误以为S08只教了"怎么问交期"这一件事。

| 需求维度 | 说明 | 甲侧重程度 | 乙侧重程度 | 本文档是否已有完整示范 |
|---|---|---|---|---|
| 交付/效率类 | 交期稳定性、生产/产线效率、自动化程度 | 高 | 高 | 已示范（S08-01至S08-08） |
| 质量/风险类 | 质量稳定性、合规风险、供应链中断风险 | 中 | 高（尤其技术/合规角色维度） | 已示范（甲：S08-09至S08-12） |
| 成本/预算类 | 采购总成本、预算周期与审批额度、隐性成本 | 中 | 高（尤其财务角色维度） | 已示范（乙：S08-13至S08-16） |
| 决策/流程类 | 内部审批流程复杂度、多方协调难度 | 低 | 高（乙决策链复杂，此维度往往是关键卡点） | 未示范，可参照上述示范自行展开 |
| 增长/战略类 | 业务扩张计划、未来采购量变化、多期合作可能性 | 低-中 | 高（尤其S类战略客户，见S04） | 未示范，可参照上述示范自行展开 |

**使用方法**：把示范中的具体话术替换为对应维度的内容，阶段逻辑（背景→难点→影响→方向确认）、追问路径结构、话术意图四维度、升级路径的设计方式保持不变。

**对AI生成话术的意义**：若需要基于本模块生成新维度或新产品线的提问话术，应先确定目标维度（参照上表），再套用本文档已示范的三条完整链条（交付/效率、质量/风险、成本/预算）的字段结构和设计模式生成对应内容，而非直接套用具体措辞，确保生成内容能覆盖真实需要挖掘的维度，而非重复单一话题。

## 四、案例公司甲（采购经理）

### 交付/效率维度

**S08-01｜背景类**

| 字段 | 内容 |
|---|---|
| 编号 | S08-01 |
| 对话对象角色 | 采购经理 |
| 标准话术 | "目前您这边这个品类大概是怎么采购的？是固定几家供应商还是会根据情况调整？" |
| 追问路径-简略回答 | "大概多久会有一次调整供应商的情况？主要是什么原因促使您考虑更换？" |
| 追问路径-详细回答 | 顺势追问难点类（S08-02）："这几家供应商里，有没有哪家在某些方面让您觉得可以再改善？" |
| 禁忌话术 | 不要一开始就问"您预算多少"，过早问预算会显得唐突且引发戒备 |
| 话术意图（四维度） | **情绪**：以轻松的了解性提问开场，避免让客户感到被审视；**信息目标**：摸清现有供应商格局，为判断切入角度做铺垫；**关系**：展现对客户业务的兴趣而非急于推销；**行动导向**：引导客户自然说出目前采购安排的细节，为后续难点提问打基础 |
| 升级路径 | 若客户对该问题也含糊回避（如"都还好"）：转换为更具体的场景提问（参照第六节防御性应对），若仍无进展，标注信息不足，本次不强行推进 |

**S08-02｜难点类**

| 字段 | 内容 |
|---|---|
| 编号 | S08-02 |
| 对话对象角色 | 采购经理 |
| 标准话术 | "现在合作的供应商，有没有什么地方您觉得不太满意，或者希望能改善的？" |
| 追问路径-说出难点 | "这个情况大概多久发生一次？是所有订单都这样还是特定情况下才会？" |
| 追问路径-回避/轻描淡写 | "那如果单纯从效率角度，您觉得整个采购流程里，有没有哪个环节其实可以更顺畅一些？" |
| 禁忌话术 | 不要直接问"你们现在的供应商是不是不行"，带有引导性和贬低竞品的暗示 |
| 话术意图（四维度） | **情绪**：让客户感到在帮我方"提意见"而非被推销，降低戒备；**信息目标**：挖出具体、可验证的痛点而非泛泛的不满；**关系**：不诋毁竞品，保持中立专业形象；**行动导向**：引导客户说出至少一个具体、可量化的问题 |
| 升级路径 | 若追问2轮仍只得到"还行""都差不多"这类回应：判断可能是客户防御心理强或确无明显不满，转向影响类提问试探（S08-03），或标注信息不足待下次接触 |

**S08-03｜影响类**

| 字段 | 内容 |
|---|---|
| 编号 | S08-03 |
| 对话对象角色 | 采购经理 |
| 标准话术 | "如果交期不稳定的情况持续，对您这边的生产排期影响大吗？" |
| 追问路径-轻描淡写 | "大概会导致停线多久？这种情况一年大概出现几次？" |
| 追问路径-表现出重视 | 可直接推进方向确认类提问（S08-04），不需要继续深挖影响 |
| 禁忌话术 | 不要用"这样不是很麻烦吗"这种带评判色彩的反问，容易让客户觉得被说教 |
| 话术意图（四维度） | **情绪**：让客户自己意识到问题的实际代价，而非被我方灌输"你有问题"；**信息目标**：获取具体、量化的影响程度，为后续方案价值论证提供依据；**关系**：保持客观陈述而非渲染焦虑；**行动导向**：让客户主动认可"这个问题值得解决"，为方向确认铺垫 |
| 升级路径 | 若客户始终无法说出具体影响（可能确实影响很小）：不强行论证影响很大，如实标注该痛点优先级不高，转向其他需求维度或直接进入方向确认，避免过度渲染引起反感 |

**S08-04｜方向确认类**

| 字段 | 内容 |
|---|---|
| 编号 | S08-04 |
| 对话对象角色 | 采购经理 |
| 标准话术 | "如果我们能在交期稳定性上给您更明确的保障，是不是会优先考虑我们？" |
| 追问路径-认同 | 自然过渡到方案/报价环节 |
| 追问路径-犹豫或提出其他条件 | "除了交期，还有没有其他您比较看重的地方？"（回到难点类S08-02重新挖掘被忽略的维度，或参照第三节切换至其他需求维度） |
| 禁忌话术 | 不要在客户还没充分表达难点时就急于问这个，显得准备不足 |
| 话术意图（四维度） | **情绪**：给客户一个明确表态的机会，而非模糊带过；**信息目标**：确认交期是否为客户真正的决策权重项；**关系**：不过早锁定单一维度作为决策依据，避免方案设计后发现理解片面；**行动导向**：获得客户对"交期保障能否影响决策"的明确态度，作为后续方案设计的依据 |
| 升级路径 | 参照本文档第二节"整体升级路径"：若四阶段走完客户仍未给出明确方向，暂缓方案设计，先重新评估角色或补充信息 |

### 质量/风险维度（新增示范）

**S08-09｜背景类**

| 字段 | 内容 |
|---|---|
| 编号 | S08-09 |
| 对话对象角色 | 采购经理 |
| 标准话术 | "目前这批货到您那边之后，验收流程大概是怎么做的？" |
| 追问路径-简略回答 | "验收主要看哪几个指标？是每批次都全检还是抽检？" |
| 追问路径-详细回答 | 顺势追问难点类（S08-10）："验收过程中有没有遇到过批次质量不稳定，需要退换货的情况？" |
| 禁忌话术 | 不要直接问"你们验收严不严格"，容易被理解为质疑对方管理水平而非了解流程 |
| 话术意图（四维度） | **情绪**：以了解流程的姿态切入，不引起对质量问题的防御心理；**信息目标**：了解客户验收标准和流程严格程度，判断其对质量的敏感度；**关系**：展现对客户内部流程的尊重和兴趣；**行动导向**：为难点类提问铺垫具体的验收场景细节 |
| 升级路径 | 若客户对验收流程回答含糊：改用更具体的场景提问（如"上次收到货大概检查哪些方面"），仍无进展则标注信息不足 |

**S08-10｜难点类**

| 字段 | 内容 |
|---|---|
| 编号 | S08-10 |
| 对话对象角色 | 采购经理 |
| 标准话术 | "验收过程中有没有遇到过批次质量不稳定或者需要退换货的情况？" |
| 追问路径-说出难点 | "大概多久出现一次这种情况？主要集中在哪类产品或哪个供应商？" |
| 追问路径-回避/轻描淡写 | "那如果从批次一致性角度，您觉得有没有可以进一步提升的空间？" |
| 禁忌话术 | 不要直接问"是不是之前供应商以次充好"，过于直接指控性的措辞会让客户不适 |
| 话术意图（四维度） | **情绪**：以中性、专业的方式探讨质量问题，避免让客户觉得在挑拨与老供应商的关系；**信息目标**：挖出具体的质量事故频率和类型；**关系**：保持客观陈述，不诋毁竞品供应商；**行动导向**：引导客户说出至少一次具体的质量问题案例 |
| 升级路径 | 若追问2轮仍无具体案例：判断质量可能确实不是当前痛点，转向影响类试探性提问，或切换到其他需求维度 |

**S08-11｜影响类**

| 字段 | 内容 |
|---|---|
| 编号 | S08-11 |
| 对话对象角色 | 采购经理 |
| 标准话术 | "这种质量问题发生时，对您下游客户或者生产进度有没有造成影响？" |
| 追问路径-轻描淡写 | "大概造成过什么具体损失？比如退换货处理耽误了多久？" |
| 追问路径-表现出重视 | 可直接推进方向确认类提问（S08-12） |
| 禁忌话术 | 不要替客户下结论"这肯定影响很大"，让客户自己说出真实感受 |
| 话术意图（四维度） | **情绪**：让客户意识到质量问题的连锁影响，而非停留在"退换货麻烦"这一表层；**信息目标**：获取质量问题对下游客户关系、生产计划的实际影响程度；**关系**：客观陈述，不夸大问题制造焦虑；**行动导向**：为方案中质检可追溯性卖点（参照S02-02）的引入做铺垫 |
| 升级路径 | 若客户始终认为影响不大：如实标注该维度优先级较低，不强行论证，转向其他更受客户重视的维度 |

**S08-12｜方向确认类**

| 字段 | 内容 |
|---|---|
| 编号 | S08-12 |
| 对话对象角色 | 采购经理 |
| 标准话术 | "如果我们能提供更完善的批次质检报告和可追溯机制，是不是能帮您减少这类风险？" |
| 追问路径-认同 | 自然过渡到方案/报价环节，可引入S02-02质检可追溯性卖点 |
| 追问路径-犹豫或提出其他条件 | "除了质量追溯，还有没有其他您更看重的地方？"（回到难点类或切换至其他需求维度） |
| 禁忌话术 | 不要在客户明确表示质量不是主要顾虑时，仍强行推销质检卖点 |
| 话术意图（四维度） | **情绪**：确认质量维度是否值得作为方案设计重点；**信息目标**：判断质量追溯能力能否成为差异化竞争点；**关系**：不过度承诺质检能力，避免后续兑现压力；**行动导向**：获得客户对"质量追溯能否影响决策"的明确态度 |
| 升级路径 | 参照本文档第二节"整体升级路径" |

## 五、案例公司乙（技术把关人→分管领导/财务，含角色跳转说明）

**角色跳转说明（重要前提）**：技术把关人、财务、分管领导通常**不在同一场对话中**，销售需要在角色之间做信息桥接，而非假设后续角色凭空知道前面聊了什么。具体操作：完成与某一角色的对话后，销售应先将了解到的情况和该角色的态度**整理成简要书面/口头汇报材料**，在安排与下一角色的沟通前先行同步（可结合S05"关键角色接触受限时的应对策略"一并使用）。

### 交付/效率维度

**S08-05｜背景类（技术把关人）**

| 字段 | 内容 |
|---|---|
| 编号 | S08-05 |
| 对话对象角色 | 技术把关人 |
| 标准话术 | "咱们这条产线目前的自动化程度大概是怎样的？现在主要还是靠人工哪些环节？" |
| 追问路径-简略回答 | "这些人工环节大概占整体产能的多大比例？" |
| 追问路径-详细回答 | 顺势追问难点类（S08-06）："这些环节里，有没有因为人工操作导致过一致性或效率上的问题？" |
| 禁忌话术 | 不要用过于笼统的"你们现在技术怎么样"，显得不专业、不了解对方产线情况 |
| 话术意图（四维度） | **情绪**：以专业提问建立技术层面的信任；**信息目标**：了解产线自动化现状，判断改造空间；**关系**：展现专业度而非泛泛而谈；**行动导向**：为难点类提问铺垫具体的产线场景细节 |
| 升级路径 | 若技术把关人回答含糊：改用更具体的场景提问，仍无进展则标注信息不足，考虑是否角色识别有误（参照S05识别置信度） |

**S08-06｜难点类（技术把关人）**

| 字段 | 内容 |
|---|---|
| 编号 | S08-06 |
| 对话对象角色 | 技术把关人 |
| 标准话术 | "有没有遇到过因为设备/工艺问题导致停产或者效率打折扣的情况？大概多久发生一次？" |
| 追问路径-说出难点 | "这个问题具体是哪个环节触发的？之前有没有尝试过什么解决方式，效果怎么样？" |
| 追问路径-回避 | "那如果从整体效率角度，您觉得目前产线有没有还能再优化的空间？" |
| 禁忌话术 | 不要问过于笼统的"有什么问题吗"，技术把关人需要具体、专业的问题才愿意展开 |
| 话术意图（四维度） | **情绪**：以技术交流姿态而非推销姿态获取信任；**信息目标**：挖出具体的技术痛点和发生频率；**关系**：展现专业度，为后续技术方案的可信度打基础；**行动导向**：获取至少一个具体、可验证的技术难点 |
| 升级路径 | 若追问2轮仍无具体内容：判断可能确无明显技术痛点，或该把关人掌握信息有限，转向影响类试探或标注信息不足 |

|---|---|
| 编号 | S08-07 |
| 对话对象角色 | 技术把关人 |
| 标准话术 | "这种停产/效率问题，大概会造成多大的产能损失？对整体交付计划有没有影响？" |
| 追问路径-轻描淡写 | "如果按年度计算，这种情况大概会造成多少产能上的损失？" |

| 话术意图（四维度） | **情绪**：让技术把关人自行意识到问题的量化代价；**信息目标**：获取具体的产能损失数据，为方案价值论证提供依据；**关系**：客观陈述，不夸大问题；**行动导向**：为向分管领导汇报积累具体、可信的数据支撑 |
| 升级路径 | 若技术把关人认为影响有限：如实记录，不强行论证，可能意味着该维度不是本次项目的核心驱动因素 |

**S08-08｜方向确认类（分管领导）**

| 字段 | 内容 |
|---|---|
| 编号 | S08-08 |
| 对话对象角色 | 分管领导 |
| 前提动作 | 开场前需已完成与技术把关人信息的桥接同步（见本节"角色跳转说明"），确保本轮提问的信息基础真实存在 |
| 标准话术 | "基于目前了解到的产线情况，如果我们能提供一个既解决效率问题、又能控制在预算范围内的方案，是不是符合您这边的整体考虑？" |
| 追问路径-认同 | 自然过渡到方案设计环节，可提议安排现场勘测 |
| 追问路径-犹豫或修正方向 | "除了效率提升，在预算或实施周期上，您这边有没有特别的顾虑？"（回到难点类重新挖掘或切换需求维度） |

| 升级路径 | 参照本文档第二节"整体升级路径"：若分管领导态度依然模糊，暂缓推进方案设计，重新评估是否遗漏了关键决策角色 |

| 编号 | S08-13 |

## 六、客户防御性强/不愿深入回答时的应对

| 情况 | 应对方式 |
|---|---|
| 客户简单带过、不愿展开（如只说"还行吧"） | 换一个更具体的场景化提问（如"比如说上个月有没有类似情况"），具体场景比抽象问题更容易打开话匣子 |
| 客户明显有所保留（涉及内部信息或竞品比较） | 不强行追问，转而通过后续多次接触逐步建立信任后再了解，参照S05内部教练识别方法 |
| 追问2-3轮仍无实质内容（非防御，而是确实不掌握信息） | 参照本文档第二节通用兜底规则，记录为信息不足，转向其他角色或后续接触 |

## 七、本模块专属验收细则

| 检查点 | 标准 |
|---|---|
| 提问逻辑顺序正确 | 是否按"背景→难点→影响→方向确认"的顺序设计，不能一上来就是封闭式提问 |
| 追问路径完整 | 每个首层提问是否配有至少两种典型回答对应的追问路径，而非只有一层问题 |
| 问题具体不笼统 | 是否针对具体场景提问，而非"有什么需求吗"这种笼统问法 |
| 角色针对性体现 | 面对不同角色的提问内容是否体现其关注点差异（参照S05） |
| 角色跳转是否交代清楚 | 涉及多角色接力提问的场景，是否说明信息如何在角色间桥接，而非默认后一角色凭空知晓前情 |
| 单阶段兜底与整体升级路径均存在 | 是否区分"单阶段内追问无果"和"四阶段走完仍无方向"两种不同层级的兜底/升级处理 |
| 话术意图四维度完整 | 情绪、信息目标、关系、行动导向四项均需填写，不能只写一两项 |
| 编号完整 | 每条提问条目是否有唯一编号，格式是否符合字段规范 |
| 需求维度是否讲清楚可迁移性 | 是否至少有两个不同维度的完整示范链条，而非只讲道理没有第二个可对照实例 |

## 八、课件页要点

1. 讲解"先开放后封闭"的提问逻辑，避免学员把提问做成审讯式的一连串封闭式问题。
2. **讲清楚需求维度清单与四阶段逻辑的正交关系**：本文档已示范交付/效率、质量/风险、成本/预算三个维度的完整链条，学员需要理解同样的四阶段逻辑还可套用到决策流程、增长战略等维度上。
3. 强调追问路径不是死板脚本，而是"根据对方回答走不同分支"的决策树思维，需要现场判断客户属于哪种回答类型。
4. 讲解乙场景下的角色跳转和信息桥接，避免学员想当然地认为可以对下一个角色直接说"基于我们聊的情况"却没有做过信息同步。
5. 讲解两层兜底/升级路径的区别：单阶段问不出是"换个问法或换个人问"，四阶段走完仍无方向是"暂缓推进方案、重新评估角色"，层级不同，处理方式也不同。
6. 现场练习：让学员两两一组，一人扮演客户、一人按提问逻辑现场挖掘"痛点"，导师点评提问顺序、追问路径选择是否恰当；额外增加一轮练习，要求学员将四阶段逻辑套用到决策流程或增长战略维度上，自行设计一条新的完整链条，检验对需求维度清单的迁移应用能力。
