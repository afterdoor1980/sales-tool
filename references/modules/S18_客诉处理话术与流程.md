# S18 客诉处理话术与流程

> 版本：v1.0（正式稿）
> 篇章：十一、售后服务篇
> 模板类型：混合（类型C1处理流程 + 类型A安抚/解决话术）
> 适用业务模式：甲乙差异明显（乙客诉往往涉及更高风险和更正式的处理程序）
> 前置依赖：S17（服务响应超时等情况会转入本模块）、S04（分层影响处理优先级和让步空间）、S03（客诉严重程度可能影响客户诚意重新评估）
> 模块目的：让客诉发生时有章可循，及时化解而非升级，保护客户关系和企业口碑

---

## 一、客诉严重程度分级（处理前必读）

| 等级 | 判定标准 | 响应时限（标准） | 处理权限（标准） | 分层影响（关联S04） |
|---|---|---|---|---|
| 轻微 | 使用体验类问题，未造成实质损失（如包装破损但产品完好） | 24小时内响应 | 一线人员自主处理 | S/A类可压缩至12小时内响应，一线人员自主让步空间可适当放宽；B/C类按标准执行 |
| 一般 | 造成一定损失但可协商解决（如批次质量问题导致部分退换货） | 4小时内响应 | 主管介入协助处理 | S/A类可压缩至2小时内响应，且一线人员可在无需逐级请示的情况下先行提出补偿方案安抚，事后补报主管；B/C类按标准执行，需主管先行确认方案再对客户承诺 |
| 严重 | 造成重大损失、涉及安全问题、或客户情绪强烈升级（如威胁曝光/诉讼） | 1小时内响应 | 公司高层必须介入，法务同步评估 | 分层不改变响应时限和高层介入要求（严重级别对所有分层一视同仁，因涉及重大风险不应因分层而有差异），但S/A类的后续补偿方案可给予更大弹性空间 |

## 二、案例公司甲 客诉处理流程

| 编号 | 步骤序号 | 具体动作 | 责任人/角色 | 产出物/检查点 |
|---|---|---|---|---|
| S18-01 | 1 | 接收客诉，判断严重程度（参照第一节分级标准，结合客户分层调整响应时限） | 客服/拜访销售 | 客诉记录，标注严重程度等级及客户分层 |
| S18-02 | 2 | 核实问题具体情况（涉及产品的需核对批次、质检记录） | 拜访销售/质检部门 | 核实结果，明确责任归属。**若核实责任不在我方**：参照第四节S18-13处理路径，不直接进入解决方案环节 |
| S18-03 | 3 | 提出解决方案并与客户沟通确认 | 拜访销售（一般以上需主管参与） | 客户认可的解决方案 |
| S18-04 | 4 | 执行解决方案（退换货/赔偿等） | 相关执行部门 | 执行完成确认 |
| S18-05 | 5 | 处理完成后回访确认客户满意度 | 拜访销售 | 满意度确认记录，若仍不满意转入第五节升级机制 |

## 三、案例公司乙 客诉处理流程

| 编号 | 步骤序号 | 具体动作 | 责任人/角色 | 产出物/检查点 |
|---|---|---|---|---|
| S18-06 | 1 | 接收客诉，判断严重程度，涉及安全或合规问题立即上报法务 | 项目负责人 | 客诉记录，严重程度等级及客户分层 |
| S18-07 | 2 | 组织技术团队核实问题（如设备故障原因排查） | 技术负责人 | 技术核实报告。**若核实责任不在我方**：参照第四节S18-13处理路径 |
| S18-08 | 3 | 提出解决方案，涉及重大损失需公司高层参与谈判 | 项目负责人（严重级别需公司高层） | 双方确认的解决方案（书面记录） |
| S18-09 | 4 | 执行解决方案（维修/赔偿/合同调整等） | 技术团队/财务 | 执行完成确认，书面记录留档 |
| S18-10 | 5 | 处理完成后安排正式回访，评估客户关系修复情况 | 项目负责人 | 回访报告，若仍不满意转入第五节升级机制 |

## 四、客诉话术

**S18-11｜通用：客户情绪激动时的安抚开场**

| 字段 | 内容 |
|---|---|
| 编号 | S18-11 |
| 对话对象角色 | 通用 |
| 场景/触发条件 | 客户情绪激动、言辞激烈提出投诉 |
| 标准话术 | "非常理解您现在的心情，这个问题确实给您带来了困扰，我先记录一下具体情况，我们会尽快核实并给您一个解决方案。" |
| 禁忌话术 | 不要在客户情绪激动时立即辩解或反驳（即使客户描述有误），先安抚情绪、核实事实优先于争辩对错；不要用"这不是我们的问题"这类推卸责任的表述，即使责任尚未明确 |
| 话术意图（四维度） | **情绪**：先接住客户的负面情绪，让其感到被重视和倾听，而非被辩解或对抗；**信息目标**：在情绪缓和后获取核实问题所需的具体信息；**关系**：即使问题严重，也要先保住基本的沟通渠道，避免情绪对抗导致升级；**行动导向**：让客户愿意配合提供更多细节，转入核实环节 |
| 升级路径 | 若客户情绪持续激烈、无法正常沟通：可礼貌建议稍后再联系或更换更高层级人员接听，不在客户情绪顶点时强行推进解决方案讨论 |
| 使用注意 | 安抚不等于无原则道歉承诺，避免在事实未核实前就承诺具体赔偿方案 |

**S18-12｜通用：解决方案沟通话术（核实后确认责任在我方）**

| 字段 | 内容 |
|---|---|
| 编号 | S18-12 |
| 对话对象角色 | 通用 |
| 场景/触发条件 | 核实完成、确认责任在我方后，向客户提出解决方案 |
| 标准话术 | "经过核实，这个问题是[具体原因]，我们的解决方案是[具体方案]，预计[时间]内完成。您看这样处理是否可以？" |
| 禁忌话术 | 不要含糊说"我们会尽快处理"而不给具体方案和时间；不要在原因未明确前就归咎于客户使用不当，避免二次激化情绪 |
| 话术意图（四维度） | **情绪**：用具体、明确的方案让客户感到问题被认真对待，减少不确定感带来的焦虑；**信息目标**：确认客户是否认可该方案，是否还有其他诉求；**关系**：以解决问题为导向而非推诿责任，维护长期信任；**行动导向**：获得客户对方案的明确认可，进入执行环节 |
| 升级路径 | 若客户不认可提出的方案：了解具体不满意的点，评估是否可调整方案（参照第一节权限分级决定是否需要上报）；若多轮协商仍无法达成一致：转入第五节升级机制 |
| 使用注意 | 方案应基于第一节的处理权限范围内提出，超出权限的方案需先经审批再对客户承诺 |

**S18-13｜通用：核实后确认责任不在我方的沟通话术（新增）**

| 字段 | 内容 |
|---|---|
| 编号 | S18-13 |
| 对话对象角色 | 通用 |
| 场景/触发条件 | 核实后确认问题是客户自身操作不当，或产品/服务本身无质量问题 |
| 标准话术 | "经过核实，这个情况可能是[具体原因，如使用环境/操作方式]导致的，从我们这边的记录和检测来看，产品/服务本身是符合标准的。虽然这不属于我们的责任范围，但如果您需要，我们可以提供一些使用建议，或者以有偿协助的方式帮您解决当前的问题。" |
| 禁忌话术 | 不要直接说"这是你的问题，跟我们没关系"这种生硬否定的表述，容易激化情绪；不要在没有充分核实依据的情况下就武断归咎于客户 |
| 话术意图（四维度） | **情绪**：既清晰说明立场，又不让客户感到被指责或被抛弃，保留服务空间；**信息目标**：让客户理解核实的过程和依据，而非单方面否认；**关系**：即使不承担直接责任，也通过提供建议或有偿协助维护长期关系；**行动导向**：让客户接受核实结果，同时评估是否需要有偿协助 |
| 升级路径 | 若客户不认可核实结果、坚持认为责任在我方：可提议引入第三方检测或提供更详细的核实依据（如检测报告、操作记录）；若客户情绪依然激烈：参照S18-11安抚后重新沟通，避免陷入反复争辩 |
| 使用注意 | 需确保核实过程和依据真实、经得起客户质疑，不能仅凭主观判断就下结论 |

## 五、客户对处理结果仍不满意的升级机制

| 情况 | 处理方式 |
|---|---|
| 客户对方案执行结果仍不满意 | 由更高层级（主管/公司高层）直接介入沟通，不再由原一线人员反复解释；重新评估是否需要提供超出原方案的补偿 |
| 客户情绪持续激烈甚至威胁负面曝光/诉讼 | 立即上报公司高层及法务，按危机处理预案沟通，不由一线人员自行承诺或对抗 |
| 多轮处理后客户依然不满意但问题本身已合理解决 | 如实记录处理过程和已提供的方案，避免无限满足客户不合理的额外诉求，同时参照第六节判断是否存在重复投诉/疑似恶意投诉信号 |

## 六、重复投诉/疑似恶意投诉的识别机制（新增，与S03存疑/信息不足逻辑打通）

参照S03已建立的"存疑"（有明确负面信号）与"信息不足"（尚不确定）状态区分原则，对重复投诉做具体判断：

| 状态 | 具体判断标准 | 处理方式 |
|---|---|---|
| 信息不足（暂不判定为恶意） | 同一客户短期内投诉2次及以下，或投诉内容涉及不同具体问题 | 按常规流程正常处理，不预设立场 |
| 存疑（疑似恶意投诉，需谨慎处理） | 同一客户3个月内投诉超过3次，且诉求模式高度相似（如均要求超出问题实际损失的赔偿/补偿），或在核实结果明确无责任的情况下仍反复以类似理由投诉 | 转交主管评估，处理时同步保留完整的核实证据链（检测记录、沟通记录），不由一线人员单独决定是否满足其诉求；必要时可考虑重新评估该客户在S03中的诚意判定状态 |

**处理原则**：即使判定为"存疑"，仍需按流程正常核实和沟通，不应未经核实就直接拒绝或区别对待，避免误伤真实存在问题的客户；只是在提供补偿/让步时更加谨慎，且相关决策需要主管介入而非一线自行判断。

## 八、本模块专属验收细则

| 检查点 | 标准 |
|---|---|
| 严重程度分级明确 | 是否给出具体判定标准和对应的响应时限、处理权限 |
| 分层影响是否体现 | 是否说明不同客户分层在响应时限、处理权限上的差异，而非分级标准对所有客户一视同仁 |
| 流程步骤顺序合理 | 是否体现真实先后关系 |
| 安抚话术在核实之前 | 是否强调先安抚情绪再核实事实，而非上来就辩解或推诿 |
| 责任不在我方的处理是否覆盖 | 是否有专门话术处理核实后责任不在我方的情况，而非默认核实结果都是需要我方担责 |
| 重复投诉识别标准具体 | 是否给出具体的次数/时间阈值，而非笼统说"评估是否恶意" |
| 升级机制存在 | 是否说明客户对结果仍不满意时该如何处理 |
| 与S24衔接 | 是否说明严重客诉应形成复盘记录，作为失败案例素材 |
| 甲乙差异体现 | 乙是否体现法务/技术团队介入等更正式的处理程序 |

## 九、课件页要点

1. 强调"先安抚情绪，再核实事实，最后谈方案"的处理顺序，避免上来就辩解引发情绪对抗。
2. 讲解严重程度分级和对应权限，以及分层如何影响响应时限和处理弹性，避免一线人员在超出权限范围内自行承诺，也避免对高价值客户反应迟缓。
3. 讲解"核实后责任不在我方"时如何得体沟通，既不冤枉公司担责，也不激化客户情绪。
4. 讲解重复投诉的具体识别标准，避免笼统地凭感觉判断"这个客户是不是想讹钱"。
5. 现场练习：给学员多个模拟客诉场景（含责任在我方、责任不在我方、疑似重复投诉三种情况），让其按流程和话术处理，导师用验收细则点评。
