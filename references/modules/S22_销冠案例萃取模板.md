# S22 销冠案例萃取模板

> 版本：v1.0（正式稿）
> 篇章：十三、案例篇
> 模板类型：类型E（案例萃取类）
> 适用业务模式：甲乙对比
> 前置依赖：全部前序模块（销冠案例可能涉及任何场景）、S03（判断经验是否可复制）
> 模块目的：把销冠的隐性经验转化为组织可复制的显性知识，防止人走了经验就没了

---

## 一、与S23/S24的边界说明

**S22是萃取方法论和模板**（怎么问、怎么记录、怎么判断是否可复制），**S23（成功案例十例）、S24（失败案例复盘十例）是用S22方法萃取出来的、经筛选后正式收录进手册的具体案例内容**。三者关系是"方法论→原始萃取记录→精选正式收录"，S22本身不直接呈现10个完整案例，只提供1-2个示范用例展示方法怎么用。

---

## 二、核心萃取方法论：RCA法

> **命名说明**：本模块的"RCA法"特指"Record记录层—Clue线索层—Abstract抽象层"这套经验萃取技术方法，与质量管理领域"Root Cause Analysis（根因分析）"是同一缩写但不同含义，使用时如涉及对外场景（如向有质量管理背景的客户介绍），建议加以说明避免混淆。

隐性经验之所以难以复制，是因为销冠自己说出来的话往往停留在"具体行为"层面，中间缺了一步"抽象"的过程。RCA法就是把这个抽象过程本身拆解成可操作的技术步骤：

| 层级 | 内容 | 怎么得到 |
|---|---|---|
| **R（Record）记录层** | 销冠具体做了什么、说了什么——尽量逐字记录，不做任何概括或美化 | 用第三节"情境还原类"问题获取（"当时具体说了什么"） |
| **C（Clue）线索层** | 销冠在那个当下，依据什么具体信号/线索做出了这个选择，而不是别的选择 | 用第三节"决策过程类""反事实推演类"问题获取（"你当时怎么判断该这么做的""换个做法结果会不同吗"） |
| **A（Abstract）抽象层** | 把线索层的判断逻辑，**剥离掉这个具体客户/产品的细节**，提炼成一条"如果出现XX信号，则采取XX应对方向"的可迁移规则 | 萃取导师主导完成，需要主动做"去情境化"的抽象动作，而非让销冠自己总结 |

**关键技术要点**：抽象层的提炼**不能由销冠自己完成**——这正是"直接问销冠你的经验是什么"通常得到空话的根本原因：销冠停留在记录层（做了什么），最多到线索层（当时怎么想的），但"剥离具体情境、提炼可迁移规则"这个抽象动作，需要萃取导师作为"局外人"主动去做，销冠本人反而因为太熟悉细节而难以跳出来看到抽象规律。

### RCA法应用示例（对应S22-01案例）

| 层级 | 内容 |
|---|---|
| R 记录层 | "客户说XX厂报价更低，销冠没有让价，反问了一句'他们的报价包含质检报告和补货承诺吗'" |
| C 线索层 | 追问销冠为什么这么问，得到："我们做这行久了知道，客户说的低价很多时候没对比过全部条款，与其纠结价格数字，不如先确认对方是不是在比同一件事" |
| A 抽象层（萃取导师完成） | 剥离"质检报告""补货承诺"这些具体产品条款，抽象为：**当客户用竞品低价施压时，先确认对比基准是否对等（是否涵盖同等的隐性条款），而非直接在价格数字上正面回应**——这就是S11-05最终固化的通用逻辑 |

## 三、萃取引导问题清单（RCA法的信息采集工具）

直接问销冠"你是怎么成功的"，通常只能得到笼统答案（"就是用心服务呗"）。需要用结构化提问引导其说出具体细节：

| 提问类型 | 示例问题 | 对应RCA层级 |
|---|---|---|
| 情境还原类 | "当时具体是什么情况？客户当时说了什么、你怎么回应的？" | 采集R记录层 |
| 决策过程类 | "在那个节点，你当时是怎么判断该怎么做的？有没有想过用别的方式？" | 采集C线索层 |
| 反事实推演类 | "如果换一种做法，你觉得结果会不一样吗？为什么？" | 辅助验证C线索层的判断依据 |
| 可复制性类 | "你觉得这个做法换到别的客户身上还管用吗？什么情况下可能不管用？" | 为萃取导师完成A抽象层提供参考边界 |

## 四、萃取实施流程（类型C1，将RCA法及其他要点组织成完整步骤）

| 编号 | 步骤序号 | 具体动作 | 责任人/角色 | 产出物/检查点 |
|---|---|---|---|---|
| S22-03 | 1 | 筛选候选案例：从销冠近期成交记录中，选取有代表性、且销冠本人愿意分享的案例（参照第五节心理障碍应对） | 萃取导师/主管 | 候选案例清单 |
| S22-04 | 2 | 结构化访谈：使用第三节引导问题清单，按RCA法逐层采集R记录层、C线索层信息 | 萃取导师 | 访谈记录（尽量逐字记录关键对话，而非事后概括） |
| S22-05 | 3 | 完成A抽象层提炼：萃取导师主导剥离具体情境细节，提炼可迁移规则；按第六节模板字段整理案例 | 萃取导师 | 案例初稿（含初步规律假设） |
| S22-06 | 4 | 可复制性判断：按第七节标准，判断是"真规律"还是"运气/关系导致"，决定是否写入可复制规律 | 萃取导师+资深销售评审 | 判断结论及依据。**若判定为运气/关系导致**：转为S23案例素材保留，不写入可复制规律部分 |
| S22-07 | 5 | 交叉验证：与其他销冠或历史案例比对，检验规律是否在多个案例中都成立 | 资深销售评审组 | 交叉验证记录。**若发现矛盾**：参照第八节矛盾处理机制 |
| S22-08 | 6 | 关联既有模块话术编号，形成正式案例条目 | 萃取导师 | 完整案例条目（含话术编号引用） |
| S22-09 | 7 | 提交决定是否收录进S23（成功）或S24（失败复盘） | 主管/内容评审组 | 收录决定 |

## 五、销冠参与萃取的心理障碍与应对

**常见障碍**：
- 担心"教会徒弟饿死师傅"，不愿毫无保留分享真正的关键做法
- 低估自身经验价值（"我也没什么特别的，就是运气好/关系好"），导致萃取内容流于表面

**应对方式**：
- 建立激励机制：萃取贡献计入绩效考核加分项，或在最终手册中保留署名（如"本方法来自XX的实战经验"），把贡献经验转化为个人品牌价值而非纯粹的无偿输出
- 萃取导师在访谈时明确说明："分享经验不会削弱你的地位，反而是对你专业能力的正式认可和证明"，减少防御心理
- 若销冠仍有保留，不强求，可先从相对愿意分享的销冠开始，用实际的正向反馈（如署名认可、加分兑现）逐步建立信任，带动更多人愿意参与

## 六、萃取模板字段说明（类型E标准结构）

| 字段 | 说明 |
|---|---|
| 编号 | S22-XX |
| 案例背景 | 客户情况、业务模式（甲/乙），需具体而非笼统 |
| 关键决策点 | 谈单过程中的转折/难点，即"如果这里处理不好，结果可能就不一样"的节点（对应RCA的R记录层） |
| 销冠动作/话术 | 具体怎么做的，可引用相关模块话术编号（对应RCA的R记录层） |
| 结果 | 成交/失败及原因 |
| 可复制规律 | 从个案抽象出的通用方法论，需经RCA法的C、A两层推导及第七节质量判断确认后填写 |

## 七、示范案例（RCA法应用范例）

**S22-01｜甲：案例萃取示范**

| 字段 | 内容 |
|---|---|
| 编号 | S22-01 |
| 案例背景 | 某中小制造企业客户，采购经理最初以竞品报价压价，采购金额约80万/年 |
| 关键决策点 | 客户提出竞品报价更低时，销冠没有立即让价，而是先追问竞品报价是否包含质检报告和补货承诺（参照S11-05逻辑） |
| 销冠动作/话术 | 追问竞品条款细节，发现客户其实并未仔细核实竞品是否有同等保障条款，随后针对性强调本方质检可追溯性和72小时补货能力，最终以接近原价成交，仅提供小幅度框架协议让步 |
| 结果 | 成交，且后续转为S15触发的稳定复购客户 |
| 可复制规律 | 客户拿竞品压价时，未必真的做过同等条件对比，主动追问细节而非立即让价，往往能发现对方比较基准不对等，这一逻辑已被固化为S11-05的标准应对话术（RCA推导过程见第二节示例） |

**S22-02｜乙：案例萃取示范**

| 字段 | 内容 |
|---|---|
| 编号 | S22-02 |
| 案例背景 | 某集团客户自动化改造项目，技术把关人对方案配置提出冗余质疑，项目金额约400万 |
| 关键决策点 | 面对"配置是否过度"的质疑，销冠没有直接反驳，而是主动提议现场逐项过配置清单（参照S11-07逻辑），并邀请技术把关人参与讨论哪些是必须项 |
| 销冠动作/话术 | 现场逐项讲解配置必要性，同时坦诚承认其中一项确实可以按需简化（参照S20劣势维度应对策略的坦诚原则），最终方案获得技术把关人认可并推荐给分管领导 |
| 结果 | 中标，且技术把关人后续成为项目推进过程中的内部教练（参照S05） |
| 可复制规律 | 面对技术质疑时，逐项透明讨论比整体辩护更容易建立信任，适度承认可优化点反而增强可信度而非削弱说服力，这一逻辑已被固化为S11-07标准应对话术 |

## 八、区分"真正可复制的规律" vs "运气或特殊关系导致的一次性成功"（质量把关）

不是所有销冠的成功案例都能提炼出可复制的规律，需要判断：

| 判断标准 | 说明 |
|---|---|
| 是否依赖不可复制的个人关系 | 若成功的关键是"销冠和客户老板私交甚好"，这不构成可复制的方法论，只能作为个案记录，不写入"可复制规律" |
| 销冠能否解释"为什么这样做有效" | 若销冠只能说"我就是这么做的，结果就成了"而无法解释背后逻辑（即C线索层采集失败），需要萃取导师进一步引导（参照第三节反事实推演类问题）挖掘深层逻辑，若始终无法解释，暂不纳入可复制规律 |
| 是否在其他案例中也能观察到类似逻辑 | 单一案例的规律需要与其他销冠案例或历史案例交叉验证，若多个案例都指向类似逻辑，可信度更高 |

**处理原则**：不能因为是销冠讲的就默认都值得复制，也不因过度严格而否定一切经验价值——依赖关系的个案仍可保留作为S23成功案例素材（展示真实商业情境），但不写入需要新人学习执行的"可复制规律"部分，避免误导新人以为靠拉关系就能复制销冠业绩。

## 九、多位销冠做法矛盾时的处理

若不同销冠对同类场景采取了不同甚至相反的做法（如销冠A面对价格异议倾向强硬不让步、销冠B倾向灵活让步，且都曾成功），不强行取其一作为唯一标准，而应：
1. 分析两种做法各自适用的具体情境差异（如客户类型、紧迫程度、客户分层）
2. 若情境差异明确，可将两种做法都保留，分别标注适用条件（类似S11的角色分支处理方式）
3. 若情境差异不明确、纯属个人风格差异，交由资深销售和管理层共同评审，判断哪种做法更具普适性、更适合作为团队标准推广，而非放任两种矛盾的"标准做法"同时存在造成混乱

## 十、本模块专属验收细则

| 检查点 | 标准 |
|---|---|
| RCA法三层逻辑完整 | 是否清楚说明记录层、线索层、抽象层各自的内容和采集方式，而非笼统的"萃取经验" |
| 与S23/S24边界清楚 | 是否说明本模块是方法论，S23/S24是精选正式收录内容 |
| 引导问题清单具体 | 是否提供具体可操作的引导问题，并与RCA层级对应 |
| 萃取流程完整 | 是否有从筛选案例到提交收录的完整步骤，而非零散要点 |
| 参与激励机制存在 | 是否说明如何应对销冠不愿分享的心理障碍 |
| 可复制性判断标准明确 | 是否给出区分"真规律"与"运气/关系"的具体判断依据，而非全盘照收 |
| 矛盾做法处理机制存在 | 是否说明不同销冠做法冲突时该如何处理 |
| 案例引用其他模块 | 示范案例是否恰当引用相关话术编号，体现萃取内容与手册体系的联动 |

## 十一、课件页要点

1. 讲解RCA法的三层结构，强调"抽象层不能由销冠自己完成，需要萃取导师主动剥离情境细节"这一关键技术要点。
2. 用S22-01示范案例完整走一遍RCA法的推导过程，让学员直观理解方法论如何应用。
3. 讲解销冠不愿分享的心理障碍及应对方式，尤其强调分享经验是个人价值的证明而非削弱。
4. 讲解如何区分"真正可复制的规律"和"运气/关系导致的一次性成功"，避免新人误以为靠拉关系就能复制业绩。
5. 讲解多位销冠做法矛盾时的处理方式，避免团队因为"两个销冠说法不一样"而无所适从。
6. 现场练习：让学员两两一组，一人扮演销冠、一人使用RCA法和引导问题清单进行模拟萃取访谈，导师点评是否完整走完记录层、线索层，并尝试独立完成抽象层的提炼。
